## 1. Развертывание Victoria Metrics

Для начала нам необходимо развернуть основной сервис, который будет хранить наши метрики  и собирать данные (метрики) с необходимых узлов.

Используем команду:
```
docker compose up -d victoria
```

Ожидаемый вывод:

```
[+] up 1/1
 ✔ Container work-victoria-1 Started                                        
 ```

Теперь перейдём на http://127.0.0.1:8428/vmui/

Мы увидим веб-интерфейс, в котором можно выполнять запросы и отслеживать метрики в реальном времени. 

![vm interface](https://i.imgur.com/8LVchob.png)

Но метрики нам пока взять негде...

## 2. Развертывание Node exporter

Метрики можно собирать с различных систем, самый базовый, но, безусловно, **необходимый** вариант - это собрать метрики о состоянии аппаратного обеспечения (загрузка процессора, оперативной памяти, дисковой подсистемы, etc) некоторой машины (в данном случае - вашего ноутбука).

Для этого мы используем сервис Node exporter из экосистемы Prometheus. Запускаем:

```
docker compose up -d node_exporter
```

Посмотреть список запущенных контейнеров можно с помощью команды:
```
docker compose ps
```

![compose-ps](https://i.imgur.com/SnvSLmP.png)

Как мы наблюдаем на скриншоте - у нас запущено два контейнера, один из которых мы запустили в предыдущем пункте, а второй - node_exporter - прямо сейчас.

Возвращаемся на http://127.0.0.1:8428/vmui.

Переходим в меню в раздел Explore -> Explore Prometheus Metrics.

Здесь вам необходимо будет выбрать Job, Instance и Metrics, которые вы хотите отобразить на графике. При наведении на каждое поле вы получите подсказку по выбору.

![metrics](https://i.imgur.com/fgcKwOW.png)

Скорее всего вы увидите очень маленькое количество данных, т.к. node_exporter был запущен не так давно - это нормально.

Хотя и визуализация данных здесь достаточно неплохая, но её может быть недостаточно, особенно, если нужно анализировать множество метрик одновременно. 

Поэтому сейчас мы поднимем инструмент, который поможет нам строить многофункциональные дашборды и визуализации.

## 3. Развертывание Grafana

### Подключение источника

Запускаем:
```
docker compose up -d grafana
```

И переходим на http://127.0.0.1:3000

Логин и пароль по умолчанию: `admin:admin`

Далее вам предложат сменить пароль - можно задать любой, например `admin1`. После этого Вы окажетесь в главном меню.

Слева в боковом меню выбираем Connections -> Data sources. На открывшейся странице нажимаем кнопку "Add data source".

Из предложенных вариантов выбираем Prometheus. Далее Вам необходимо заполнить только лишь поле "Prometheus server URL". Туда необходимо ввести значение: `http://127.0.0.1:8428`.

![grafana](https://i.imgur.com/TQiT0e7.png)

После этого пролистайте до конца страницы и нажмите "Save & test". В случае успешного подключения Вы увидите сообщение "Successfully queried the Prometheus API."

Мы успешно подключили нашу базу данных с метриками и теперь можем перейти к созданию собственных дашбордов!

### Создание Dashboard

В том же боковом меню выбрать "Dashboards" и на странице "+ Create dashboard".

Откроется окно редактирования дашборда

![dashboard edit](https://i.imgur.com/lDL4HF1.png)

Справа выберите "Panel" и добавьте новый элемент. После этого он отобразится в основной части страницы. Наведите на него мышью и нажмите "Configure visualization". Откроется следующая страница:

![panel](https://i.imgur.com/wTkv7ED.png)


Внизу отображаются сведения о запросах к нашей БД с метриками, на одном дашборде их может быть несколько. Эти запросы можно писать вручную или собирать с помощью конструктора. Мы воспользуемся конструктором.

В поле "Select metric" выбираем метрику, например, `node_load1` (*это показатель Load average за 1 минуту*). Нажимаем `Run queries` - Grafana построит нам график для **всех** наших нод, но т.к. мы мониторим толкьо одно устройство - то график будет один.

![](https://i.imgur.com/vzZSfuk.png)

Далее в правом верхнем углу нажимаем "Save" - сообщение можно не указывать и подтверждаем повторно. Далее нажимаем "Back to dashboard" и возвращаемся обратно к нашему дашборду. 

Аналогично можно добавить множество графиков (и не только!), отражающих различные метрики, но сейчас мы не будем на этом останавливаться и  перейдем к рассмотрению одному из важнейших этапов мониторинга - реагированию на события.

## 4. Настройка алертинга (vmalert + Alertmanager)

Для начала нам потребуется отредактировать файл конфигурации `alert_manager/config.yaml`. В нём необходимо указать данные (login, password, SMTP хост и порт) от вашего почтового аккаунта. Пример для Яндекс-почты приведен ниже:

```
global:
  smtp_smarthost: 'smtp.yandex.ru:465'
  smtp_from: 'your-email-address@yandex.ru'
  smtp_auth_username: 'your-email-address@yandex.ru'
  smtp_auth_password: 'your_password'
  smtp_require_tls: false
route:
  receiver: 'email-admins'
  group_by: ['alertname']
  group_wait: 10s
  group_interval: 5m
  repeat_interval: 1h
receivers:
  - name: 'email-admins'
    email_configs:
      - to: 'your-email-address@yandex.ru'
        send_resolved: true
```

Далее запускаем:
```
docker compose up -d vmalert alert_manager
```

Обратите внимание, что вывод команды
```
docker compose ps
```

должен содержать 5 запущенных контейнеров, если у Вас отображается меньше (например 4), то, возможно, возникла проблема с Alertmanager. Просмотрите логи через:

```
docker compose logs alert_manager
```

Например здесь произошла ошибка из-за неуказанных данных почтового аккаунта:
```
alert_manager-1  | time=2026-09-18T19:38:37.468Z level=ERROR source=main.go:198 msg="alertmanager exited with error" err="error loading configuration file: address <your_data>: missing port in address"
```

После этого попробуйте снова запустить контейнер Alertmanager:
```
docker compose up -d alert_manager
```

В случае, если теперь отображаются все 5 контейнеров - отлично!

Перейдите на http://127.0.0.1:8880/vmalert/groups и выберите там группу `vm_alert`.

![](https://i.imgur.com/2Ah259T.png)

Вы увидите, что один из алертов находится в состоянии `firing` (так и задумано!), т.е. это означает, что правило в алерте сработало, и теперь Alertmanager в течение минуты отправит уведомление на почту.

Проверьте ваш почтовый ящик (и папку Спам)! Туда должно было прийти письмо от Alertmanager с уведомлением о высокой загрузке.

![](https://i.imgur.com/hSvf58C.png)

## Очистка окружения

Для того, чтобы всё остановить, используйте:
```
docker compose down
```

Чтобы удалить все данные приложений (кроме конфигов, которые находятся в work):
```
docker compose down -v
```
