## 0. Первоначальная настройка
**Если при попытке сделать первый коммит Git ругается ("Please tell me who you are"), нужно представиться системе**:
* `git config --global user.name "Ваше Имя"` — задать имя, которое будет отображаться в авторах коммита.
* `git config --global user.email "ваш.email@example.com"` — задать email автора.


## 1. Работа с проектом
* `git clone <url>` — клонировать удаленный репозиторий на локальную машину.
* `git add <файл>` — добавить конкретный файл в индекс (подготовить к коммиту).
* `git add .` — добавить все измененные файлы в текущей директории в индекс.
* `git commit -m "<сообщение>"` — зафиксировать подготовленные изменения (создать коммит).
* `git commit --amend` — добавить новые изменения в последний коммит или изменить его сообщение (без создания нового коммита).
* `.gitignore` — файл, внутри которого прописываются правила, какие файлы Git не должен замечать.

## 2. Работа с указателями (ветки, теги, stash)
* `git branch` — посмотреть список локальных веток.
* `git checkout <название_ветки>` — переключиться на существующую ветку.
* `git checkout -b <название_ветки>` — создать новую ветку и сразу переключиться на нее.
* `git stash` — «спрятать» незакоммиченные изменения в буфер.
* `git stash pop` — достать и применить спрятанные изменения из буфера.
* `git tag <название>` — повесить статичную метку (тег) на текущий коммит.
* `git show <название_тега>` — показать информацию о теге и коммите, на который он указывает.
* `git log --oneline --all --decorate` — вывести компактную историю всех коммитов и указателей в консоль.

## 3. Merge и Rebase
* `git merge <название_ветки>` — влить изменения из указанной ветки в текущую (создает merge-коммит, сохраняет историю двух веток).
* `git rebase <название_ветки>` — перенести коммиты текущей ветки поверх указанной (выстраивает историю в прямую линию).
* `git log --graph --oneline --decorate` — вывести историю коммитов с графическим отображением дерева веток.

## 4. Откат изменений
* `git reflog` — журнал всех перемещений указателя HEAD (помогает найти «потерянные» коммиты и вернуться к ним).
* `git reset <commit_hash>` — переместить указатель ветки на указанный коммит (меняет историю).
* `git revert <commit_hash>` — создать новый коммит, который полностью отменяет изменения указанного прошлого коммита.
* `git cherry-pick <commit_hash>` — скопировать конкретный коммит (например, из другой ветки) и применить его изменения к текущей ветке.

## 5. Worktrees (Рабочие деревья)
* `git worktree add <путь_к_новой_папке> <название_ветки>` — создать параллельную рабочую директорию (ВАЖНО! Директорию необходимо сделать на уровень выше репозитория, а не в нём!), привязанную к этому же репозиторию.
* `git worktree remove <путь_к_новой_папке>` — удалить рабочую директорию (после завершения работы).
* `git worktree list` - посмотреть список worktree в репозитории

## 6. Submodules (Подмодули)
* `git switch <название_ветки>` — переключиться на ветку (современная альтернатива `git checkout`).
* `git submodule update --init --recursive` — инициализировать, скачать и обновить содержимое всех подмодулей в проекте.

## 7. Git Hooks
* `chmod +x <имя_файла>` — сделать файл исполняемым.

### Шаблон для хука `commit-msg`
```bash
#!/bin/bash

INPUT=$1
MIN_LEN=10 # Минимальная длина сообщения коммита

LINE=$(head -n1 $INPUT)

MSG_LEN=$(echo -n "$LINE" | wc -m)

if (( MSG_LEN < MIN_LEN )); then
        echo "Слишком короткое сообщение коммита: введите "$MIN_LEN" и более символов"
        exit 1
fi
exit 0
```

## 8. Продвинутые команды (Advanced)
* `git rebase -i <commit_hash>` (interactive) — открывает редактор для управления историей. Позволяет склеивать (squash), удалять (drop), менять местами или переименовывать (reword) прошлые коммиты. Обычно передают хэш коммита *до* того места, которое хотят изменить (или `HEAD~N`).
* `git push --force-with-lease` — безопасная альтернатива `push -f`. Перезапишет историю на сервере, только если никто из коллег не успел запушить новые коммиты в эту ветку, пока вы делали локальный rebase.
* `git clean -fd` — жесткая очистка рабочей директории. Удаляет все неотслеживаемые файлы и папки (ВАЖНО! Это действие нельзя отменить, файлы удаляются физически).
* `git blame <файл>` — выводит содержимое файла, где напротив каждой строки указано, кто, когда и в каком коммите последним ее менял.
